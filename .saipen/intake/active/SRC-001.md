PROBLIP ANDROID — FEATURE WAVE: 5-MINUTE PREMIUM TRIALS + HOME SCREEN WIDGET

ROLE

You are the implementation agent.

Work on the current existing Problip Android repository.

The application is intentionally small.
Implement ONLY:

1. five-minute trials for unowned premium sounds
2. five-minute trials for unowned premium themes

==================================================
PRODUCT CONTRACT
================

FREE:

* Original Blip
* existing intervals
* volume
* Classic theme

PURCHASED:

* purchased sounds remain available permanently
* Themes Pack permanently unlocks every premium theme

TRIAL:

Any currently unowned premium sound or premium theme may be selected and used
for FIVE MINUTES.

Trial duration:

5 minutes exactly = 300_000 ms

After its trial expires:

* an unowned sound becomes unavailable again
* an unowned theme stops rendering and Classic becomes effective again

The user may start another five-minute trial later.

This is intentionally NOT a one-time trial.

However:

REPEATED SELECTION OF AN ALREADY ACTIVE TRIAL MUST NOT EXTEND ITS EXPIRATION.

Example:

12:00:00 select Glass
expires 12:05:00

12:02:00 tap Glass again
still expires 12:05:00

12:05:01 select Glass again
new trial may expire 12:10:01

Do not add cooldowns, counters, accounts, device IDs, server validation or
anti-abuse logic.

The purchase remains valuable because purchased content has no timer.

==================================================

PART 1 — SMALL TRIAL DOMAIN
===========================

Create one small Android-independent trial model.

Suggested concepts:

TrialAccess
TrialClock
TrialSnapshot / TrialState

Avoid a large architecture.

Stable trial IDs are the EXISTING content IDs:

Sounds:

sound_glass
sound_wood
sound_soft_bell
sound_bonk
sound_space

Themes:

theme_terminal
theme_phosphor
theme_midnight
theme_amber
theme_pink

Do NOT create trial IDs for:

sound_original
theme_classic
theme_pack

Ownership and trial access are different concepts.

A purchased item is OWNED.

An unowned item with a non-expired trial is TRIAL-ACCESSIBLE.

Do not merge trial access into Billing ownership.

==================================================
TRIAL PERSISTENCE
=================

Trial expiration must survive:

* Activity recreation
* process death
* app restart

Persist expiration timestamps locally using the existing DataStore setup.

A compact representation is sufficient.

For example conceptually:

trialExpiries:
sound_glass -> epochMillis
theme_pink -> epochMillis

Do NOT add Room.

Do NOT add another database.

Do NOT add WorkManager.

Use wall-clock epoch milliseconds for persisted expiry.

This is not a security boundary.
Do not build clock-tampering protection for €0.49 sounds.

All stored trial IDs must be validated against known trialable catalog entries.

Expired entries may be lazily pruned.

==================================================
TRIAL CLOCK / TESTABILITY
=========================

Time must be injectable at the pure logic boundary.

Do not scatter:

System.currentTimeMillis()

through UI/catalog/service code.

Have a tiny clock abstraction, for example:

interface TrialClock {
fun nowMillis(): Long
}

Production implementation uses wall-clock time.

Tests use fake time.

==================================================
ACTIVE TRIAL EXPIRATION
=======================

While the app process is alive, trial access must disappear at the correct
expiration time without requiring the user to reopen a screen.

This matters especially while ProblipService is RUNNING.

Implement one lightweight process-level trial manager/coordinator that:

* observes persisted trial expirations
* exposes active trial IDs
* schedules only the NEXT relevant expiration
* recomputes access when that expiration occurs
* then schedules the next one

Do NOT create a one-second background ticker for access control.

Do NOT use AlarmManager for five-minute trials.

Do NOT use exact alarms.

If the process is not alive, no background timer is required.
On next process start, persisted expiration timestamps are evaluated immediately.

A separate UI-only countdown may refresh once per second while a trial row is
visible.

==================================================
STARTING A TRIAL
================

Provide an operation conceptually like:

startTrial(contentId)

Rules:

* reject non-trialable IDs
* if content is already purchased, do not create a trial
* if a non-expired trial already exists, return the existing expiry unchanged
* otherwise store:
  now + 300_000 ms

The operation must be concurrency-safe enough that rapid repeated taps cannot
produce arbitrary extensions.

accessible if:

entry.free

OR entry.id in activeTrialIds

For themes:

accessible if:

OR Themes Pack is owned

---

## SOUND TAP RULE

FREE OR PURCHASED SOUND:

normal pool toggle

ACTIVE TRIAL SOUND:

normal pool toggle

UNOWNED + NO ACTIVE TRIAL:

tapping/selecting it must:

1. start its five-minute trial
2. add it to the selected random sound pool
3. make it immediately playable

Do NOT automatically start Problip itself.

Selecting content and starting the blip session remain separate actions.

---

## SOUND EXPIRY

When an unowned sound trial expires:

* it must immediately cease being PLAYABLE
* a RUNNING Problip session must update its prepared pool without restarting the
  scheduler
* that sound must no longer be selected visually as an effective pool member

If the expired sound was the only effective selected sound:

fallback to Original Blip.

Problip must never end up with an empty playable sound pool.

It is acceptable to retain a remembered raw preference internally if that makes
purchase/retrial restoration cleaner, BUT:

* UI must show the EFFECTIVE pool
* service must use the EFFECTIVE pool
* expired content must never continue playing

Prefer simple semantics over aggressive DataStore rewriting.

---

## PURCHASE DURING TRIAL

Example:

Glass trial has 02:13 remaining
user purchases Glass

Expected:

* Glass immediately becomes normal permanent owned content
* it remains selected/playable
* the trial timer no longer matters
* no visible reset happens at the old expiry

The stale trial record may be removed opportunistically.

PART 3 — PREMIUM THEME TRIALS
=============================

( ) Terminal       OWNED

---

## THEME TAP RULE

FREE Classic:

select normally

THEMES PACK OWNED:

select premium theme normally

UNOWNED PREMIUM THEME WITHOUT ACTIVE TRIAL:

1. start five-minute trial for THAT theme ID
2. persist/select that theme
3. render it immediately

UNOWNED PREMIUM THEME WITH ACTIVE TRIAL:

select normally without extending its timer

---

## THEME EXPIRY

If the currently rendered premium theme's trial expires and Themes Pack is
still not owned:

* effective rendered theme becomes Classic automatically
* Themes screen visually selects Classic
* no Activity restart is required

It is acceptable to remember the preferred premium theme ID internally.

That allows:

* buying Themes Pack later
* or starting a new trial later

to restore/reselect it cleanly.

But an expired trial must NEVER continue rendering the premium palette.

---

## SWITCHING BETWEEN TRIAL THEMES

Trials are PER CONTENT ITEM.

Example:

12:00 Pink trial starts -> expires 12:05
12:02 Terminal trial starts -> expires 12:07
12:03 user selects Pink again -> Pink still expires 12:05

Do not reset Pink to another five minutes.

At 12:05 Pink becomes inaccessible.

Terminal may remain trial-accessible until 12:07.

Only one theme can render at a time, naturally.

======================
